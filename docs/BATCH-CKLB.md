# Recursive OpenSCAP → CKLB conversion

[Quick start](README.md) · [Review workflow](WORKFLOW.md) · [CLI scope](GO-MIGRATION.md) · [Asset handoff](../contracts/asset-record-v1.md)

This is evidence-side conversion of saved scans, not lab provisioning or an official DISA assessment. The lab lives in a separate repository; this CLI accepts caller-supplied private paths. No ceremonial stamp is included.

Build the standalone Go CLI from the repository root (Go 1.22+; dependency is vendored for offline builds):

```sh
install -d -m 700 dist
GOPROXY=off GOSUMDB=off go build -mod=vendor -o dist/stig-evidence ./cmd/stig-evidence
```

Run from **any working directory** by using the built executable's path. In the example below, run from the repository root; replace the private paths with your own. Supply the saved-scan tree via `--input-root`; there is no compiled-in lab path. Keep extracted official manual XCCDFs in a stable, owner-private `--library-root` (subdirectories are searched):

```sh
./dist/stig-evidence batch-cklb \
  --input-root /private/inventory \
  --library-root /private/extracted-stig-library \
  --dry-run

./dist/stig-evidence batch-cklb \
  --input-root /private/inventory \
  --library-root /private/extracted-stig-library
```

The October library ZIP contains nested RHEL 9 and 10 product ZIPs; extract each required product ZIP too, so the library root contains `U_RHEL_<OS>_STIG_V<version>R<release>_Manual-xccdf.xml` files. Supply separately obtained RHEL 7 and 8 benchmarks for those families. Library directories must be owner-owned/private (0700), the XCCDF files owner-private (0600), and no symlinks are accepted. For **each scan OS**, every invocation selects the highest **numeric version, then numeric release**, cross-checking filename against the official benchmark ID, XML namespace, version and `release-info`. It prints the selected path and SHA-256, including during `--dry-run`; malformed candidates and equal highest releases in different paths fail closed. SSG result version `0.1.82` is *not* an official DISA release number. No download or ZIP extraction occurs during conversion.

Adding a new quarterly release to that root makes the **next invocation** use it, including for old scans. That is a deliberate current-benchmark reinterpretation, not a reconstruction of the benchmark in force when the scan ran; compare changed controls before compliance use. Different benchmark bytes produce distinct output filenames and do not overwrite earlier files. For a pinned historical conversion of a **single-OS tree**, use `--benchmark /private/official.xml` **instead of** `--library-root`; a mismatched OS fails. Change only `--input-root` to process a different tree (including deeply nested folders). The input directory must contain host-named leaf directories; each XCCDF `TestResult/target` must equal its containing directory's basename. The scanner needs no VM access for conversion. Run `batch-cklb --help` for flags. No global `--operator-approved` is offered: approval of one run cannot be silently extended to every scan found recursively.

## Pairing and output

The crawler recognizes `<prefix>.results.xccdf.xml` or `<prefix>.results.xml` within the same directory as optional `<prefix>.report.html`. `<prefix>.results.arf.xml` adds joined OVAL/host values when HTML also exists. XCCDF-only conversion has status mapping but no executed-check or returned host value; the checklist labels this absence and its provenance omits HTML/ARF. It ignores `.stig-viewer.xccdf.xml` (a different result representation), old CKLB files, benchmark XML and scan logs. An orphaned HTML/ARF, duplicate XCCDF for one prefix, symlink, public directory, unreadable private input, mismatched target or conflicting evidence stops with a nonzero exit; it never falls back to another run's report. Numeric `V-…`/`SV-…` matching is the default mapping convention: newer SSG `V-…` vulnerability references and older SSG `SV-…_rule` STIG references can join an official control by numeric ID, but different revision suffixes are not copied as official rule IDs. This is not proof that each SSG check is semantically identical to the official DISA check. ARF+HTML yields host-observation findings; older XCCDF+HTML scans yield only values actually rendered in HTML. Missing and ambiguous controls stay Not Reviewed.

New checklists are written **beside each run** as `<prefix>-disa-<benchmark-hash>-<versioned-input-bundle-hash>-ASSESSMENT.cklb`, with a paired `<name>.cklb.provenance.json` sidecar. The sidecar records the checklist's full SHA-256, full scan/benchmark hashes and paths, optional HTML/ARF hashes and paths when supplied, and each control's mapping reason, raw SSG rule IDs and outcomes. Its `reconciliation.rule_references` inventory records every TestResult rule-result (including unselected and unmatched): raw result/SSG rule ID, every original reference text/href, and a normalized V join key when applicable. This inventory does not make unmapped or unselected rules positive candidates; mapped per-control provenance remains in `controls[].sources`. Keep the two files together; the sidecar is a byte-identity record, **not** a signature. The versioned digest uses `assessment-provenance-v6` for conservative dual-reference mapping; v5/v4/v3/v2 outputs retain their original names. Different benchmark bytes and changed inputs have distinct filenames; files are mode `0600` in owner-private directories. A repeated run verifies both outputs before skipping. If only private source path spellings differ, it checks that the original sidecar is canonical, **every recorded source path is absolute** and still resolves to its recorded hash, and all non-path fields match the current conversion; it retains the original sidecar without rewriting it. Old relative-path sidecars cannot be accepted as equivalent because their working directory was not recorded. A differing checklist, missing original input, changed source hash, changed reconciliation, or late name collision remains an error. If sidecar creation fails after the CKLB is written, the partial pair is retained and the command fails so it can be inspected and safely retried.

These are *review* checklists, not signed DISA releases. Schema validation against the separately obtained official CKLB 1.0 JSON schema is still an external verification step. The Go batch command has no signature, policy, tailoring or release gate and does not prove SSG-to-DISA semantic check equivalence; the operator must review the unmatched, N/A and Not Reviewed controls. Host configuration data may be sensitive—do not commit or distribute the source scans or checklists casually.

## OS compatibility and verification boundary

Synthetic end-to-end Go tests convert a mixed RHEL 7/8/9/10 tree and check per-OS newest-benchmark selection, exact official IDs, no-overwrite reruns, older SSG `SV-…` references, and XML-only absence labeling. Go v6 outputs from all five real saved scans exist for **RHEL 8, 9 and 10**. Each CKLB is byte-identical to its externally schema-validated v5 counterpart; independent Go readback checked v6 benchmark ID/status pairs, source/checklist hashes, complete TestResult reference inventory and private permissions. A full-tree v6 Go rerun from another working directory skipped all five without replacing their sidecars. Older v5/v4/v3 files remain historical review outputs. The RHEL 8 guest's packaged SSG 0.1.72 content has older explicit `SV-…` STIG references, not the newer `V-…` vulnerability references; v6 numeric mapping leaves 42 of 371 official controls Not Reviewed while preserving 198 Open, 109 Not a Finding, and 22 Not Applicable candidate statuses. This does not independently prove equivalent check semantics across benchmark revisions. RHEL 7 still needs a real scan and eligible private benchmark; STIG Viewer GUI import has not been exercised. The CLI currently accepts SSG XCCDF 1.2 `stig`/`stig_gui` profiles (and the older RHEL 7 `stig-rhel7-disa` profile), DISA manual XCCDF 1.1, and the specified scan filename convention; this is not every possible OpenSCAP export or profile.

Each v6 CKLB is byte-for-byte identical to its v5 CKLB that passed external CKLB 1.0 schema validation. These are current v6 review checklists, not signed releases, and a real STIG Viewer GUI import has not been exercised.
