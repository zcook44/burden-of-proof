# Recursive OpenSCAP → CKLB conversion

[Quick start](README.md) · [Review workflow](WORKFLOW.md) · [Exact lab scan command and playbook snapshot](OSCAP-SOURCE.md) · [CLI scope](GO-MIGRATION.md) · [Asset handoff](../contracts/asset-record-v1.md)

This is evidence-side conversion of saved scans, not lab provisioning or an official DISA assessment. The lab lives in a separate repository; this CLI accepts caller-supplied private paths. No ceremonial stamp is included.

This command is **RHEL OpenSCAP only**. Cisco saved running configurations use [`cisco-cklb`](CISCO-CONFIG.md), an explicit platform/role benchmark and a separate private-input workflow; the Bash batch preflight does not validate Cisco configs. The source checkout tracks Cisco XML and all-`auto` inventories under `stig-library-cisco/`, but the generic archive excludes them.

Build the standalone Go CLI from the repository root (Go 1.22+; dependency is vendored for offline builds):

```sh
install -d -m 700 dist
GOPROXY=off GOSUMDB=off go build -mod=vendor -o dist/stig-evidence ./cmd/stig-evidence
```

Run from **any working directory** by using the built executable's path. In the example below, run from the repository root; replace the private paths with your own. Supply the saved-scan tree via `--input-root`; there is no compiled-in lab path. Keep extracted official manual XCCDFs in a stable, owner-private `--library-root` (subdirectories are searched):

```sh
./dist/stig-evidence batch-cklb \
  --input-root /private/inventory \
  --library-root /private/extracted-stig-library \
  --dry-run

./dist/stig-evidence batch-cklb \
  --input-root /private/inventory \
  --library-root /private/extracted-stig-library
```

The October library ZIP contains nested RHEL 9 and 10 product ZIPs; extract each required product ZIP too, so the library root contains `U_RHEL_<OS>_STIG_V<version>R<release>_Manual-xccdf.xml` files. Supply separately obtained RHEL 7 and 8 benchmarks for those families. Library directories must be owner-owned/private (0700), the XCCDF files owner-private (0600), and no symlinks are accepted. For **each scan OS**, every invocation selects the highest **numeric version, then numeric release**, cross-checking filename against the official benchmark ID, XML namespace, version and `release-info`. It prints the selected path and SHA-256, including during `--dry-run`; malformed candidates and equal highest releases in different paths fail closed. SSG result version `0.1.82` is *not* an official DISA release number. No download or ZIP extraction occurs during conversion.

Adding a new quarterly release to that root makes the **next invocation** use it, including for old scans. That is a deliberate current-benchmark reinterpretation, not a reconstruction of the benchmark in force when the scan ran; compare changed controls before compliance use. Different benchmark bytes produce distinct output filenames and do not overwrite earlier files. For a pinned historical conversion of a **single-OS tree**, use `--benchmark /private/official.xml` **instead of** `--library-root`; a mismatched OS fails. Change only `--input-root` to process a different tree (including deeply nested folders). The input directory must contain host-named leaf directories; each XCCDF `TestResult/target` must equal its containing directory's basename. The scanner needs no VM access for conversion. Run `batch-cklb --help` for flags. No global `--operator-approved` is offered: approval of one run cannot be silently extended to every scan found recursively.

## Per-OS checklist tailoring

Put an owner-private `RHEL_<major>_STIG.tailoring.yaml` at the `--library-root` directory (for example `RHEL_9_STIG.tailoring.yaml`) **only after authorization**. The file applies to **every host and saved scan of that OS**; do not put a host-specific decision here. `--benchmark` mode also looks beside its benchmark file. An absent OS file leaves its checklists unchanged; `rules: []` is a valid, tracked empty policy that changes no statuses (but its bytes still affect output identity). The packaged templates are **unapproved examples**: RHEL 8 V2R9 illustrates twelve `auto` entries from `rh8-r2v9-ignore-rules`; RHEL 9 V2R10 illustrates thirteen entries from `rh9-r2v10-ignore-rules` (twelve `auto` and an explicit lab-specific `not_a_finding` for passwordless sudo). RHEL 7 V3R15 and RHEL 10 V1R3 examples use empty policies because no matching remediation ignore lists were available. These ignore lists are external remediation inputs, not converter configuration or authorization. An excluded remediation alone does not establish a checklist outcome.

```yaml
rules:
  - rule_name: sudo_remove_nopasswd  # SSG rule name from the ignore file
    stig_id: V-258106               # DISA group ID
    sv_id: SV-258106r1102061_rule  # exact rule ID in the selected benchmark
    status: auto                    # auto | open | not_a_finding | not_applicable | not_reviewed
    comment: "Remediation excluded; verify the privilege policy for this control."
```

`auto` retains the scan-derived checklist status and adds the note to Comments. To answer a Not Reviewed item or correct a false positive, change `status` to the desired checklist value **only after authorization** and write the administrator's reason in `comment`. The original automated candidate and host observations remain in the checklist/provenance; the comment labels a manual decision, not approval of it. The exact V/SV pair, allowed status, nonempty comment, duplicates, unknown YAML fields, and file privacy are checked before output; none of those checks validates policy approval. Editing the policy creates a **new** versioned checklist and sidecar, which record its path and SHA-256; reruns with unchanged inputs verify and skip. Existing checklists are never overwritten. For initial deployment use the [Bash preflight](DISCONNECTED-RELEASE.md) to review benchmark and policy selections before writing.

## Pairing and output

The crawler recognizes `<prefix>.results.xccdf.xml` or `<prefix>.results.xml` within the same directory as optional `<prefix>.report.html`. `<prefix>.results.arf.xml` adds joined OVAL/host values when HTML also exists. XCCDF-only conversion has status mapping but no executed-check or returned host value; the checklist labels this absence and its provenance omits HTML/ARF. It ignores `.stig-viewer.xccdf.xml` (a different result representation), old CKLB files, benchmark XML and scan logs. An orphaned HTML/ARF, duplicate XCCDF for one prefix, symlink, public directory, unreadable private input, mismatched target or conflicting evidence stops with a nonzero exit; it never falls back to another run's report. Numeric `V-…`/`SV-…` matching is the default mapping convention: newer SSG `V-…` vulnerability references and older SSG `SV-…_rule` STIG references can join an official control by numeric ID, but different revision suffixes are not copied as official rule IDs. This is not proof that each SSG check is semantically identical to the official DISA check. ARF+HTML yields host-observation findings; older XCCDF+HTML scans yield only values actually rendered in HTML. Missing and ambiguous controls stay Not Reviewed unless an administrator explicitly tailors their checklist status.

New checklists are written **beside each run** as `<prefix>-disa-<benchmark-hash>-<versioned-input-bundle-hash>-ASSESSMENT.cklb`, with a paired `<name>.cklb.provenance.json` sidecar. The sidecar records the checklist's full SHA-256, full scan/benchmark hashes and paths, optional HTML/ARF hashes and paths when supplied, and each control's mapping reason, raw SSG rule IDs and outcomes. Its `reconciliation.rule_references` inventory records every TestResult rule-result (including unselected and unmatched): raw result/SSG rule ID, every original reference text/href, and a normalized V join key when applicable. This inventory does not make unmapped or unselected rules positive candidates; mapped per-control provenance remains in `controls[].sources`. Keep the two files together; the sidecar is a byte-identity record, **not** a signature. Untailored outputs keep the `assessment-provenance-v10` identity; per-OS YAML outputs use `assessment-provenance-v11-tailored` and include the exact policy bytes in the bundle digest. v9/v8/v7/v6 and older outputs retain their original names. Comments show the control status (and the reason when Not Reviewed); Finding Details show selected, labeled observations without raw regex predicates, repeated hashes or the misleading item-level `not evaluated` phrase when a test has already reported an outcome. No approval or verification workflow text is placed in the CKLB title or Comments. When observations are omitted or shortened, the checklist points to the unmodified private ARF/HTML; the sidecar retains exact source IDs, outcomes and references. Different benchmark bytes and changed inputs have distinct filenames; files are mode `0600` in owner-private directories. A repeated run verifies both outputs before skipping. If only private source path spellings differ, it checks that the original sidecar is canonical, **every recorded source path is absolute** and still resolves to its recorded hash, and all non-path fields match the current conversion; it retains the original sidecar without rewriting it. Old relative-path sidecars cannot be accepted as equivalent because their working directory was not recorded. A differing checklist, missing original input, changed source hash, changed reconciliation, or late name collision remains an error. If sidecar creation fails after the CKLB is written, the partial pair is retained and the command fails so it can be inspected and safely retried.

These are *review* checklists, not signed DISA releases. The pinned DISA CKLB 1.0 JSON schema is included under `schemas/`, but validation remains an **external** step (for example, Checkmate `--validate --schema`); the Go converter does not use it. The Go batch command has no signature or release gate and does not prove SSG-to-DISA semantic check equivalence; the operator must review the unmatched, N/A and Not Reviewed controls. Host configuration data may be sensitive—do not commit or distribute the source scans or checklists casually.

## OS compatibility and verification boundary

Synthetic end-to-end Go tests convert a mixed RHEL 7/8/9/10 tree and check per-OS newest-benchmark selection, exact official IDs, no-overwrite reruns, older SSG `SV-…` references, and XML-only absence labeling. Go v6 outputs from all five real saved scans exist for **RHEL 8, 9 and 10**. Each CKLB is byte-identical to its externally schema-validated v5 counterpart; independent Go readback checked v6 benchmark ID/status pairs, source/checklist hashes, complete TestResult reference inventory and private permissions. A full-tree v6 Go rerun from another working directory skipped all five without replacing their sidecars. Older v5/v4/v3 files remain historical review outputs. The RHEL 8 guest's packaged SSG 0.1.72 content has older explicit `SV-…` STIG references, not the newer `V-…` vulnerability references; v6 numeric mapping leaves 42 of 371 official controls Not Reviewed while preserving 198 Open, 109 Not a Finding, and 22 Not Applicable candidate statuses. This does not independently prove equivalent check semantics across benchmark revisions. A separate RHEL 7 V3R15 manual benchmark and real saved node1 scan are now available; that newer review candidate is not part of the five historical v6 bundles. STIG Viewer GUI import has not been independently exercised by this CLI. The CLI currently accepts SSG XCCDF 1.2 `stig`/`stig_gui` profiles (and the older RHEL 7 `stig-rhel7-disa` profile), DISA manual XCCDF 1.1, and the specified scan filename convention; this is not every possible OpenSCAP export or profile.
