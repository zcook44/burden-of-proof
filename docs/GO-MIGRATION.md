# Go-only review converter

`docket` is the command. The repository is still burden-of-proof. Build it with the environment in [install and run](README.md); the packaged static Linux/amd64 CLI needs no Go or Python runtime. Paths below use that page's `/private/stig-library`. A simple per-OS YAML supplies checklist comments and decisions, but the retired *signed-release* tailoring implementation was **not** ported. No command here verifies an approval signature, releases an official assessment, or delivers evidence. The lab, inconveniently, still lives somewhere else. See [disconnected release](DISCONNECTED-RELEASE.md), [workflow](WORKFLOW.md), and the [asset record contract](../contracts/asset-record-v1.md).

## Commands

```sh
# Build with the install-page environment, then:
./dist/docket asset-check --asset /private/asset.json --pre /private/pre.xml --host node.example.test
./dist/docket reconcile --scan /private/ssg-results.xml --benchmark /private/official.xml --out /private/candidates.json
./dist/docket draft-cklb --scan /private/ssg-results.xml --benchmark /private/official.xml --out /private/review.cklb
./dist/docket batch-cklb --input-root /private/inventory --library-root /private/stig-library
./dist/docket cisco-cklb --config /private/configs/ios-xe-switch-01/scan.running-config --target ios-xe-switch-01 --library-root /private/stig-library --benchmark-id Cisco_IOS_XE_Switch_L2S_STIG --dry-run
./dist/docket cisco-batch --manifest /private/cisco-manifest.json --evidence-root /private/configs --library-root /private/stig-library --output-root /private/cisco-review --dry-run
./dist/docket cisco-xccdf --config /private/evidence/ios-xe-switch-01/scan.running-config --target ios-xe-switch-01 --fqdn ios-xe-switch-01.example.test --ip 192.0.2.4 --mac 02:00:00:00:00:04 --role "Access switch" --target-type "Cisco IOS-XE switch" --library-root /private/stig-library --benchmark-id Cisco_IOS_XE_Switch_L2S_STIG --out /private/scans/ios-xe-switch-01/ios-xe-switch-01.Cisco_IOS_XE_Switch_L2S_STIG.results.xml
./dist/docket xccdf-cklb --results /private/scans/ios-xe-switch-01/ios-xe-switch-01.Cisco_IOS_XE_Switch_L2S_STIG.results.xml --library-root /private/stig-library --out /private/checklists/Cisco_IOS_XE_Switch_L2S_STIG/ios-xe-switch-01/ios-xe-switch-01.cklb
```

- `asset-check` verifies a v1 asset record against the supplied pre-scan bytes. It does **not** attest lab provenance, baseline state, or authorization.
- `reconcile` creates private candidate mapping JSON, never an official DISA scan result. Every TestResult rule-result (including unmatched and unselected) retains raw outcome, original reference text/href, and any numeric V join key. Ambiguous source references cannot establish a passing control.
- `draft-cklb` creates a no-overwrite private checklist. `--assessment-view --html-report` adds executed-check/observed-value presentation; optional `--arf` adds collected OVAL values. `--operator-approved` is only an unsigned caller assertion for a single ARF assessment view, not a release gate or signature.
- `batch-cklb` recurses a host inventory and independently selects the newest eligible extracted manual benchmark for each detected RHEL 7/8/9/10 OS. It reads optional per-OS YAML at the library root, then writes one private CKLB and byte-bound provenance sidecar per saved scan. Untailored outputs retain the v10 identity; tailored outputs use a separate v11 identity bound to the policy bytes. Earlier outputs remain unchanged. [Exact pairing, library and no-overwrite rules](BATCH-CKLB.md).
- `cisco-cklb` accepts one saved `.running-config` under the exact target-named private directory and one exact Cisco manual XCCDF (or an owner-private library plus exact benchmark ID). Optional `--port-roles` is a CSV of interface roles. Pinned checks may set Not a Finding, Open, or Not Applicable for IOS, IOS-XE, and NX-OS switch controls whose official check text still matches; every other control stays Not Reviewed. A schema v3 root file lists only administrator decisions. It does not infer a benchmark or turn arbitrary config lines into compliance. [Cisco input and evidence boundaries](CISCO-CONFIG.md).
- `cisco-batch` reads a manifest of hosts, platforms, and exact benchmark IDs. Each host directory supplies `scan.running-config` and, for switch checks, `port-roles.csv`. It writes one private CKLB, provenance sidecar, and HTML review page per benchmark under `--output-root/<benchmark-id>/<host>/`, plus `index.html`. The hostname command must match the directory name. Dry-run prints the four status counts and writes nothing.
- `cisco-xccdf` writes an XCCDF 1.2 TestResult for one saved configuration. The `hostname` command must equal `--target`. `--out` must be `<host>/<host>.<benchmark-id>.results.xml`. `--fqdn`, `--ip`, `--mac`, `--role`, and `--target-type` are required and are stored as target facts. The FQDN begins with the hostname. A tailoring file beside the configuration is applied to the result. [Network scan](NETWORK-SCAN.md).
- `xccdf-cklb` reads that result and writes `<host>/<host>.cklb`, `<host>.cklb.provenance.json`, the review page, and the tailoring worksheet. Statuses come from the result file. The checklist target page receives the hostname, FQDN, IP, MAC, role, and technology area recorded on the scan. The provenance sidecar binds the checklist bytes to the result file, the benchmark, and the running-config SHA-256. [Admin walkthrough](NETWORK-ADMIN-WALKTHROUGH.md).

A numeric `V-…` or historical `SV-…r…_rule` reference is an explicit join candidate, not independently verified check-equivalence. Missing, unselected, ambiguous, or unchecked controls remain Not Reviewed unless an administrator explicitly supplies a per-OS checklist decision. The packaged binary has converted copied real scans for all four RHEL families with their official benchmarks and bundled YAML templates; GUI import has not been exercised by this CLI. Keep scans, operational benchmark copies, review files, and sidecars private and out of Git (the tracked Cisco reference library is a deliberate exception, not an operational input tree).

The source checkout tracks 25 Cisco manual XML benchmarks and 25 partial schema v3 root tailoring files under `stig-library-cisco/`. The manuals are absent from the generic runtime archive. Checkout permissions do not meet private-input requirements, so stage an authorized `0700` library before use. Manuals may be `0644`. Tailoring stays `0600`. An empty `rules` list is not a verdict.

For initial offline deployment, `docket quarter --dry-run` checks tailoring and previews every configured platform without writing. `--cisco` and `--rhel` select one platform. A platform with no inputs is skipped unless you asked for it with that flag. `scripts/preflight-offline.sh` checks private trees and exits non-zero when `tailoring check` fails. `checkmate` is the second binary in this module (`cmd/checkmate`). It inventories and edits CKLBs; it is not a converter or an approval gate. Pass `--root` or set `checklist_root`. The bundled per-OS YAML templates are unapproved examples. Their `benchmark_sha256` is `rehash-me` until `docket tailoring rehash`. The connected build needs Go 1.22 or newer. The packaged binaries need no Go. See [release and preflight](DISCONNECTED-RELEASE.md) and the [quarterly runbook](QUARTERLY-RUNBOOK.md).
