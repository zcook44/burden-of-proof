# Go-only review converter

`stig-evidence` is the sole tracked application. Build it with the environment in [install and run](README.md); the packaged static Linux/amd64 CLI needs no Go or Python runtime. Paths below use that page's `/private/stig-library`. A simple per-OS YAML supplies checklist comments and decisions, but the retired *signed-release* tailoring implementation was **not** ported. No command here verifies an approval signature, releases an official assessment, or delivers evidence. The lab, inconveniently, still lives somewhere else. See [disconnected release](DISCONNECTED-RELEASE.md), [workflow](WORKFLOW.md), and the [asset record contract](../contracts/asset-record-v1.md).

## Commands

```sh
# Build with the install-page environment, then:
./dist/stig-evidence asset-check --asset /private/asset.json --pre /private/pre.xml --host node.example.test
./dist/stig-evidence reconcile --scan /private/ssg-results.xml --benchmark /private/official.xml --out /private/candidates.json
./dist/stig-evidence draft-cklb --scan /private/ssg-results.xml --benchmark /private/official.xml --out /private/review.cklb
./dist/stig-evidence batch-cklb --input-root /private/inventory --library-root /private/stig-library
./dist/stig-evidence cisco-cklb --config /private/configs/ios-xe-switch-01/scan.running-config --target ios-xe-switch-01 --library-root /private/stig-library --benchmark-id Cisco_IOS_XE_Switch_L2S_STIG --dry-run
./dist/stig-evidence cisco-batch --manifest /private/cisco-manifest.json --evidence-root /private/configs --library-root /private/stig-library --output-root /private/cisco-review --dry-run
./dist/stig-evidence cisco-xccdf --config /private/evidence/ios-xe-switch-01/scan.running-config --target ios-xe-switch-01 --fqdn ios-xe-switch-01.example.test --ip 192.0.2.4 --mac 02:00:00:00:00:04 --role "Access switch" --target-type "Cisco IOS-XE switch" --library-root /private/stig-library --benchmark-id Cisco_IOS_XE_Switch_L2S_STIG --out /private/scans/ios-xe-switch-01/ios-xe-switch-01.Cisco_IOS_XE_Switch_L2S_STIG.results.xml
./dist/stig-evidence xccdf-cklb --results /private/scans/ios-xe-switch-01/ios-xe-switch-01.Cisco_IOS_XE_Switch_L2S_STIG.results.xml --library-root /private/stig-library --out /private/checklists/Cisco_IOS_XE_Switch_L2S_STIG/ios-xe-switch-01/ios-xe-switch-01.cklb
```

- `asset-check` verifies a v1 asset record against the supplied pre-scan bytes. It does **not** attest lab provenance, baseline state, or authorization.
- `reconcile` creates private candidate mapping JSON, never an official DISA scan result. Every TestResult rule-result (including unmatched and unselected) retains raw outcome, original reference text/href, and any numeric V join key. Ambiguous source references cannot establish a passing control.
- `draft-cklb` creates a no-overwrite private checklist. `--assessment-view --html-report` adds executed-check/observed-value presentation; optional `--arf` adds collected OVAL values. `--operator-approved` is only an unsigned caller assertion for a single ARF assessment view, not a release gate or signature.
- `batch-cklb` recurses a host inventory and independently selects the newest eligible extracted manual benchmark for each detected RHEL 7/8/9/10 OS. It reads optional per-OS YAML at the library root, then writes one private CKLB and byte-bound provenance sidecar per saved scan. Untailored outputs retain the v10 identity; tailored outputs use a separate v11 identity bound to the policy bytes. Earlier outputs remain unchanged. [Exact pairing, library and no-overwrite rules](BATCH-CKLB.md).
- `cisco-cklb` accepts one saved `.running-config` under the exact target-named private directory and one exact Cisco manual XCCDF (or an owner-private library plus exact benchmark ID). Optional `--port-roles` is a CSV of interface roles. Pinned checks may set Not a Finding, Open, or Not Applicable for IOS, IOS-XE, and NX-OS switch controls whose official check text still matches; every other control stays Not Reviewed. An optional complete per-benchmark YAML inventory defaults to `auto`; explicit, commented administrator overrides are separate decisions. It does not infer a benchmark or turn arbitrary config lines into compliance. [Cisco input and evidence boundaries](CISCO-CONFIG.md).
- `cisco-batch` reads a manifest of hosts, platforms, and exact benchmark IDs. Each host directory supplies `scan.running-config` and, for switch checks, `port-roles.csv`. It writes one private CKLB, provenance sidecar, and HTML review page per benchmark under `--output-root/<benchmark-id>/<host>/`, plus `index.html`. The hostname command must match the directory name. Dry-run prints the four status counts and writes nothing.
- `cisco-xccdf` writes an XCCDF 1.2 TestResult for one saved configuration. The `hostname` command must equal `--target`. `--out` must be `<host>/<host>.<benchmark-id>.results.xml`. `--fqdn`, `--ip`, `--mac`, `--role`, and `--target-type` are required and are stored as target facts. The FQDN begins with the hostname. A tailoring file beside the configuration is applied to the result. [Network scan](NETWORK-SCAN.md).
- `xccdf-cklb` reads that result and writes `<host>/<host>.cklb`, `<host>.cklb.provenance.json`, the review page, and the tailoring worksheet. Statuses come from the result file. The checklist target page receives the hostname, FQDN, IP, MAC, role, and technology area recorded on the scan. The provenance sidecar binds the checklist bytes to the result file, the benchmark, and the running-config SHA-256. [Admin walkthrough](NETWORK-ADMIN-WALKTHROUGH.md).

A numeric `V-…` or historical `SV-…r…_rule` reference is an explicit join candidate, not independently verified check-equivalence. Missing, unselected, ambiguous, or unchecked controls remain Not Reviewed unless an administrator explicitly supplies a per-OS checklist decision. The packaged binary has converted copied real scans for all four RHEL families with their official benchmarks and bundled YAML templates; GUI import has not been exercised by this CLI. Keep scans, operational benchmark copies, review files, and sidecars private and out of Git (the tracked Cisco reference library is a deliberate exception, not an operational input tree).

The source checkout **does** track 25 Cisco manual XML benchmarks and 25 all-`auto` tailoring inventories (1,096 controls) under `stig-library-cisco/`. They are absent from the generic runtime archive; checkout permissions do not meet private-input requirements, so stage an authorized `0700`/`0600` copy before use. An inventory is not a verdict on 1,096 controls.

For initial offline deployment, the separately packaged Bash `scripts/preflight-offline.sh` checks private scan/library trees and any `SHA256SUMS`, then calls the Go `batch-cklb --dry-run` before an intentional conversion write. Optional separately installed Checkmate inventories existing CKLBs and can validate them with a supplied schema; it is **not** a Go subcommand, converter, or approval gate. The bundled per-OS YAML templates (including a RHEL 9 lab-specific status override) are unapproved examples, not site policy; copying them to the selected library activates their decisions for every host of that OS. See [release and preflight](DISCONNECTED-RELEASE.md) and [review boundary](WORKFLOW.md#checkmate-is-a-separate-tool).
