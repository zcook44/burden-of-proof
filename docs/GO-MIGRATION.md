# Go CLI migration (incremental)

The Go binary implements read-only `asset-check`, offline candidate reconciliation, single-scan draft CKLB generation, and recursive `batch-cklb` review conversion from saved RHEL 9 SSG OpenSCAP results and an official DISA RHEL 9 XCCDF 1.1 benchmark. For batch conversion, `--library-root` selects the newest extracted RHEL 9 benchmark on every invocation by numeric version/release with filename and metadata cross-checks; `--benchmark` remains an explicit historical override. SSG scan version is not a DISA release identifier, so old scans are deliberately remapped to the current release in library mode. Numeric V/SV matching is the default mapping convention; unresolved or ambiguous source outcomes stay Not Reviewed. It does not generate an official DISA scan, tailoring, cryptographic approvals, or released evidence. Python remains the release implementation; its current XCCDF 1.2-only policy gate does not accept the downloaded DISA manual XCCDF 1.1 without separately reviewed compatibility work. See [BATCH-CKLB.md](BATCH-CKLB.md) for directory traversal, no-overwrite handling and the exercised real tree.

From the repository root on Linux with Go 1.22+:

```sh
go test ./...
go build -o /private/bin/stig-evidence ./cmd/stig-evidence
/private/bin/stig-evidence asset-check --asset /private/asset.json --pre /private/pre.xml --host node.example.test
/private/bin/stig-evidence reconcile --scan /private/ssg-results.xml --benchmark /private/official-rhel9-xccdf.xml --out /private/new-candidates.json
/private/bin/stig-evidence draft-cklb --scan /private/ssg-results.xml --benchmark /private/official-rhel9-xccdf.xml --out /private/new-MAPPED-DRAFT.cklb
/private/bin/stig-evidence draft-cklb --assessment-view --scan /private/ssg-results.xml --html-report /private/ssg-report.html --benchmark /private/official-rhel9-xccdf.xml --out /private/new-HTML-ASSESSMENT.cklb
/private/bin/stig-evidence draft-cklb --assessment-view --scan /private/ssg-results.xml --html-report /private/ssg-report.html --arf /private/ssg-results.arf.xml --benchmark /private/official-rhel9-xccdf.xml --out /private/new-ARF-ASSESSMENT.cklb
```

`asset-check` requires owner-owned regular input files with no group/other permissions, opens them without following final-component symlinks, reads each once, and validates the v1 asset contract against the supplied pre-scan bytes. It makes no writes. Exit 0 means the record is structurally valid and its stated pre-scan hash matches the supplied bytes; exit 2 means validation or input inspection failed. Neither result attests the producing lab's Git commit, actual guest state, or approval authority.

`reconcile` requires the same private input-file protections and an owner-private existing output parent. It creates a new `0600` JSON file without replacing an existing entry. It pins the source and benchmark SHA-256, preserves the original SSG result IDs/outcomes, and emits official DISA group and rule IDs copied from the supplied benchmark. References to DISA vulnerability IDs (`V-…`) are **mapping candidates**, not proof of semantically equivalent checks. Missing, unselected, ambiguous, or non-pass/non-fail/non-notapplicable outcomes stay `not_reviewed`; a mapped failure is `open`, only unambiguous mapped passes become candidate `not_a_finding`, and a completely mapped set of `notapplicable` checks becomes candidate `not_applicable`. The JSON uses `candidate_status`, not an official DISA XCCDF result or CKLB status. Review every source, rule mapping and manual control before any official use. A 0 exit means reconciliation was produced, **not** that the guest is compliant. The output is not a supported input to the Python `cklb` release command.

`draft-cklb` independently reconciles the supplied scan and benchmark, writes a new private `.cklb` file, copies all exact official group/rule IDs and benchmark metadata, and places source SSG observations, mapping reason, and input hashes in `finding_details`. It maps matching numeric `V-…` (SSG vulnerability reference and DISA group) and `SV-…` (official DISA rule) IDs by default: unambiguous mapped `pass` becomes CKLB `not_a_finding`, mapped `fail` becomes `open`, and completely mapped `notapplicable` becomes `not_applicable`. Missing, unselected, ambiguous, not-checked, mixed-applicability, and other outcomes stay `not_reviewed`; review automated N/A before compliance use. It rejects malformed or numerically mismatched official V/SV pairs. The mapping method is recorded in the CKLB title/comments, but numeric correspondence does not prove that the underlying checks are semantically identical. No official DISA scan result, exception approval, or ISSO acceptance is asserted. The CLI currently performs structural checks only; for the real runs, outputs were separately validated with Python `stig_evidence.cklb.validate_cklb_schema` against the official DISA CKLB 1.0 schema, read back, and checked against all official ID pairs. Treat these `.cklb` files as drafts, never released checklists. Do not feed them into `stig_evidence.cli cklb` or mistake schema validity for STIG Viewer import proof.

With `--html-report`, the private OpenSCAP HTML report supplies executed OVAL test names/IDs/results to `finding_details` and each available item-state comparison plus the observed item fields to `comments`. The exact report SHA-256 is included, and mapped HTML rule outcomes must match the XCCDF outcomes or generation fails. Not all checks expose an item-state row: the generated checklist explicitly says when a comparison or executed check is absent rather than inventing one. This may produce long comments for checks with many observed items. Keep the HTML report private and from the same scan; a matching rule outcome does not prove common provenance or approval.

With `--arf` (requires `--html-report`), the converter also joins the same-run ARF XCCDF rule and OVAL definition/test/collected-object/item to include host-collected fields in `finding_details` and raw XCCDF rule, OVAL test, and item-state results plus returned fields in `comments`. Field values are quoted without whitespace normalization. For a test with no collected item, it records the ARF object's flag and `check_existence` when available (for example, an observed object absence), not an invented item value. The ARF target and every mapped rule outcome must agree with the source XCCDF and HTML; unresolved collected-item/object references fail generation. This does not independently prove equivalent DISA check semantics, and ARF/HTML matching IDs/results alone are not cryptographic proof that files came from one scan. Keep all raw artifacts private; comments may be long and contain configuration data.

## Assessment-view presentation (node2 rerun)

For an operator-approved, **unsigned** review checklist, add `--assessment-view --operator-approved` to `draft-cklb --html-report ... --arf ...`. `--assessment-view` requires an HTML report; HTML-only evidence is allowed, but `--operator-approved` additionally requires ARF. The normal detailed draft remains available. The assessment-view CKLB puts the executed OVAL check and observed host fields in `finding_details`; `comments` begin PASS/FAIL/N/A/NOT REVIEWED and show test/item results with returned fields or the observed absence condition. Repeated observations are deduplicated. A large control shows the first decisive values and visibly reports omitted observations; field text longer than 1800 Unicode characters is visibly truncated. **The complete unmodified values remain in the private ARF/HTML**. Do not treat a composite rule pass as a pass for every OVAL item. Missing/ambiguous checks remain Not Reviewed. No hash/mapping boilerplate is repeated in individual findings; the adjacent private `.cklb.provenance.json` sidecar binds the exact CKLB bytes to full raw-input hashes and retains all per-control source IDs, outcomes and mapping reasons. Keep it with the CKLB. ARF bytes affect checklist identity. This sidecar is not a signature, and the separate approval record does not become a signed release. Batch conversion always uses this view, without applying an approval to every run.
