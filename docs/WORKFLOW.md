# Go review conversion workflow

This repository owns evidence-side validation, SSG-to-CKLB review policy and conversion; the lab is provisioned and scanned in a **separate repository**. Its [versioned, non-secret asset record](../contracts/asset-record-v1.md) is a handoff, not an attestation. Install and the command table live in [install and run](README.md). [Batch rules](BATCH-CKLB.md) · [RHEL picture](RHEL-OSCAP-WORKFLOW.md) · [Cisco picture](CISCO-SCAN-PROCESS.md) · [CLI scope](GO-MIGRATION.md).

The numbered steps below are one RHEL OpenSCAP review after that install. The operator sequence for repeating the whole RHEL and Cisco run each quarter, when new manuals are published, is [QUARTERLY-RUNBOOK.md](QUARTERLY-RUNBOOK.md). Cisco uses `docket` and the same library. Pick `cisco-cklb`, `cisco-batch`, or `cisco-xccdf` plus `xccdf-cklb` from the command table. Pinned checks fill a status when the running configuration proves the official finding sentence. Every other control stays Not Reviewed, and that device's tailoring suggestion records why. Copy the edited file beside `scan.running-config` as `<benchmark-id>.tailoring.yaml` to apply it to that device. A file beside the benchmark still applies to every device that does not have its own copy. The source repo tracks 25 Cisco XML/policy pairs, but a private staged copy is required and the generic archive omits them. The checkout's file modes are a polite way of saying "not yet."

For one saved Cisco configuration, [`cisco-xccdf`](NETWORK-SCAN.md) writes an XCCDF result named for the device, and [`xccdf-cklb`](NETWORK-SCAN.md) copies it into a checklist named for that device plus a provenance sidecar. The `hostname` command must match the device name. The checklist target page carries the hostname, FQDN, management IP, management MAC, role, and technology area supplied with the scan. [Demo walkthrough](NETWORK-ADMIN-WALKTHROUGH.md).

1. Collect saved OpenSCAP SSG STIG-profile results outside this repository. The lab [playbook snapshot and exact scan command](OSCAP-SOURCE.md) show how the current Ansible workflow creates and fetches them; this Go tool does not run that playbook. The live wrapper accepts `--limit INVENTORY_HOST` and preserves initially running VM state, but a real run updates guest SCAP packages. Its playbook verifies the exact installed `stig_gui` profile with `oscap info` and scans once without remediation. A separately authorized remediation/recheck process must create a fresh scan if changes are made. Arrange the private inventory as host-named directories with same-prefix XCCDF, optional HTML, and optional ARF files. The XCCDF target must match the directory basename. If the lab supplies an asset record, `docket asset-check --asset /private/asset.json --pre /private/pre.xml --host node.example.test` validates its fields and supplied pre-scan bytes separately; batch conversion does not consume that record or prove the asserted baseline.
2. Obtain and independently pin extracted official DISA manual XCCDF benchmarks for each OS. Put them in a private benchmark library. The packaged `templates/RHEL_<major>_STIG.tailoring.yaml` files are examples **not approved site policy** (RHEL 9 includes a lab-specific override); install a reviewed and authorized per-OS policy at mode 0600 only if appropriate, or omit it. Any installed policy affects every host of that OS. On the initial offline deployment run `./scripts/ceasefire-preflight.sh --converter /private/docket --input-root /private/inventory --library-root /private/stig-library` before conversion: it checks private trees and any checksum manifests and calls converter `--dry-run`, not a scan or checklist write. Confirm the selected newest benchmark and optional policy paths/hashes before proceeding.
3. Run `docket batch-cklb --input-root /private/inventory --library-root /private/stig-library`. The Go CLI writes owner-private, no-overwrite CKLB **review** files and byte-bound provenance sidecars beside each scan. It never runs a scanner, remediates a machine, or approves findings.
4. The scan admin confirms every in-scope host has a checklist and that every rule has a status, a comment, finding details, and the manual's check text. Compare the official V/SV ID pairs, the status, and the input and checklist hashes. Security then opens each host's CKLB in STIG Viewer and judges every rule, including every Not a Finding.

**No signed release path exists in this repository.** Per-OS YAML applies checklist status/comment decisions; the former signed-policy, ledger-signature, official-scan release and atomic evidence-publication implementation was retired rather than presented as equivalent. A human or separately authorized system must handle approval, exception acceptance, signing, evidence delivery, and release. A hash proves byte identity, not scan authenticity, approval, or semantic equivalence of SSG and DISA checks. Keep raw scans, checklists, sidecars and keys private and out of Git. See [batch converter](BATCH-CKLB.md), [disconnected release](DISCONNECTED-RELEASE.md) and [asset contract](../contracts/asset-record-v1.md) for precise boundaries.

## checkmate edits a site fact

`checkmate` ships in the same archive as `docket`. Security does not run it. The scan admin can use it to record a fact the scan cannot see, such as required banner text or an approved log host, and to export only those shared administrator decisions. Pass **both** `--checkmate` and `--checklist-root` to `ceasefire-preflight.sh` to run `checkmate --list`. Optional `--schema` additionally runs `--validate`. That inventory is not conversion, a STIG Viewer import, approval, or evidence publication. Editing a checklist in checkmate makes the converter sidecar hash stale. A machine Not a Finding stays out of the tailoring export. The quarterly sequence is [QUARTERLY-RUNBOOK.md](QUARTERLY-RUNBOOK.md).
