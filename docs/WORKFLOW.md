# Go review conversion workflow

1. Collect saved OpenSCAP SSG STIG-profile results outside this repository. Arrange the private inventory as host-named directories with same-prefix XCCDF, optional HTML, and optional ARF files. The XCCDF target must match the directory basename.
2. Obtain and independently pin extracted official DISA manual XCCDF benchmarks for each OS. Put them in a private benchmark library; the Go CLI chooses the newest eligible release for each source OS. Confirm the selected paths and SHA-256 values with `batch-cklb --dry-run`.
3. Run `stig-evidence batch-cklb --input-root /private/inventory --library-root /private/extracted-stig-library`. The Go CLI writes owner-private, no-overwrite CKLB **review** files and byte-bound provenance sidecars beside each scan. It never runs a scanner, remediates a machine, or approves findings.
4. Independently validate the CKLB against the official CKLB 1.0 schema; compare every official V/SV ID pair, status, raw-reference inventory and input/checklist hash. Review all Open, N/A, ambiguous and Not Reviewed controls, and import a representative checklist into STIG Viewer before operational adoption.

**No signed release path exists in this repository.** The former tailoring, ledger-signature, official-scan release and atomic evidence-publication implementation was retired rather than presented as equivalent to Go review conversion. A human or separately authorized system must handle approval, exception acceptance, signing, evidence delivery, and release. A hash proves byte identity, not scan authenticity, approval, or semantic equivalence of SSG and DISA checks. Keep raw scans, checklists, sidecars and keys private and out of Git. See [batch converter](BATCH-CKLB.md) and [asset contract](../contracts/asset-record-v1.md) for precise boundaries.
