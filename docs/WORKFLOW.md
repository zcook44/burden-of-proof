# Go review conversion workflow

This repository owns evidence-side validation, SSG-to-CKLB review policy and conversion; the lab is provisioned and scanned in a **separate repository**. Its [versioned, non-secret asset record](../contracts/asset-record-v1.md) is a handoff, not an attestation. [Start here](README.md) · [Batch rules](BATCH-CKLB.md) · [CLI scope](GO-MIGRATION.md).

1. Collect saved OpenSCAP SSG STIG-profile results outside this repository. The lab [playbook snapshot and exact scan command](OSCAP-SOURCE.md) show how the current Ansible workflow creates and fetches them; this Go tool does not run that playbook. The live wrapper accepts `--limit INVENTORY_HOST` and preserves initially running VM state, but a real run updates guest SCAP packages. Its playbook verifies the exact installed `stig_gui` profile with `oscap info` and scans once without remediation. A separately authorized remediation/recheck process must create a fresh scan if changes are made. Arrange the private inventory as host-named directories with same-prefix XCCDF, optional HTML, and optional ARF files. The XCCDF target must match the directory basename. If the lab supplies an asset record, `stig-evidence asset-check --asset /private/asset.json --pre /private/pre.xml --host node.example.test` validates its fields and supplied pre-scan bytes separately; batch conversion does not consume that record or prove the asserted baseline.
2. Obtain and independently pin extracted official DISA manual XCCDF benchmarks for each OS. Put them in a private benchmark library. The packaged `templates/RHEL_<major>_STIG.tailoring.yaml` files are examples **not approved site policy** (RHEL 9 includes a lab-specific override); install a reviewed and authorized per-OS policy at mode 0600 only if appropriate, or omit it. Any installed policy affects every host of that OS. On the initial offline deployment run `./scripts/preflight-offline.sh --converter /private/stig-evidence --input-root /private/inventory --library-root /private/extracted-stig-library` before conversion: it checks private trees and any checksum manifests and calls converter `--dry-run`, not a scan or checklist write. Confirm the selected newest benchmark and optional policy paths/hashes before proceeding.
3. Run `stig-evidence batch-cklb --input-root /private/inventory --library-root /private/extracted-stig-library`. The Go CLI writes owner-private, no-overwrite CKLB **review** files and byte-bound provenance sidecars beside each scan. It never runs a scanner, remediates a machine, or approves findings.
4. Independently validate the CKLB against the official CKLB 1.0 schema; compare every official V/SV ID pair, status, raw-reference inventory and input/checklist hash. Review all Open, N/A, ambiguous and Not Reviewed controls, and import a representative checklist into STIG Viewer before operational adoption.

**No signed release path exists in this repository.** Per-OS YAML applies checklist status/comment decisions; the former signed-policy, ledger-signature, official-scan release and atomic evidence-publication implementation was retired rather than presented as equivalent. A human or separately authorized system must handle approval, exception acceptance, signing, evidence delivery, and release. A hash proves byte identity, not scan authenticity, approval, or semantic equivalence of SSG and DISA checks. Keep raw scans, checklists, sidecars and keys private and out of Git. See [batch converter](BATCH-CKLB.md), [disconnected release](DISCONNECTED-RELEASE.md) and [asset contract](../contracts/asset-record-v1.md) for precise boundaries.

## Checkmate is a separate tool

If Checkmate is installed separately, pass **both** `--checkmate /private/checkmate/checkmate` and `--checklist-root /private/checklists` to the Bash preflight to run Checkmate `--root ... --list`; optional `--schema /private/schema.json` additionally runs `--validate --schema ...`. Without both Checkmate arguments, omit `--schema` as well. This inventory/schema check is not conversion, a STIG Viewer import, approval, or evidence publication. Checkmate is not included in this repository's archive.
